# 默认玩法与界面方案 · 可评审草案

项目入口：[README](../README.md)。当前决策与进度见 [STATUS](../STATUS.md)。本方案落实已确认的“短局休闲、可以拼分、轻松但有挑战”方向，允许完整重构；不是已实现功能或已验证平衡。

## 一套克制的首版推荐

每局有清晰终点，玩家通过移动躲避、选择射击位置和抓住高价值目标拼分。自动射击降低持续按键负担，逐步加压保留紧张感；失败后能快速再来，不以永久升级决定成绩。

**首次试玩参数建议：150 秒一局、3 次受击容错。** 目标区间约 2–3 分钟；这些数值由方案提出，不是用户指定，须根据试玩调整。时间到或容错耗尽即结算；计时使用有效游戏时间，暂停/后台不消耗局长。

建议节奏：前约 30 秒识别控制和敌机，中段增加组合与移动判断，最后约 30 秒达到压力高点。具体波次和密度待测试；不得用随机必死墙或难以识别的碰撞制造难度。给初学者完成一局的可能，也让熟练玩家通过路线选择获得更高分。

首版保留少量易辨识敌机：基础目标和需要选择站位的高价值目标即可；暂不堆 Boss、技能树、装备、养成、商店、付费或实时联机。少量即时道具可以作为节奏变化，但不能依赖极低概率的强道具决定榜首；类型、时长与掉落数值另做试玩表，尚未定稿。

## 操作与公平视野

- 手机：优先竖屏，单指相对横向拖动；飞机保持在下方固定纵向区域，自动射击，避免手指直接遮住飞机。
- 桌面：鼠标横向移动控制；保持与手机相同的逻辑场地宽高比例和可见范围，宽屏不获得额外视野。
- 可建议桌面方向键/A-D 作为辅助输入，但属于候选，不当作已有功能或首版硬性承诺。
- 边界、缩放、像素渲染与碰撞使用统一逻辑坐标；触摸不触发整页滚动，输入取消和失焦清空控制状态。
- 推荐手机横屏时暂停并提示旋转，桌面居中显示竖向场地；行为仍须评审。

## 计分与榜单

默认使用清晰的固定击破分数，不引入隐藏分数规则或付费加成。高价值目标应有明显视觉标识，结算能解释分数来源。首版暂不依赖复杂连击倍率；是否增加完成奖励等细节需经试玩后确定。

**比较单位是相同规则版本、相同挑战种子。** 默认推荐每日固定挑战种子，用一致的敌机/道具生成序列降低随机运气差异；主菜单和榜单显示挑战标识与规则版本。挑战切换时区、种子周期和重试次数展示属于待定参数，不假定已获批准。练习局若使用不同随机种子，需与可比较榜单分开。

允许快速多次尝试，以同一玩家/匿名标识的最佳有效成绩上榜；不能沿用“IP+浏览器特征等于可靠设备身份”的假设。优先匿名休闲体验，是否跨设备同步账号后定，不强制首局注册。

同版本/同种子仅减少规则与运气差异，**不能阻止伪造分数**。公开榜需要服务端分配 run ID、幂等提交、规则/时长/分数范围检查、限流和可靠存储；若要称为可信排名，应验证可重放输入日志/服务端校验等方案。未完成验证时只作为测试榜或明确标识的娱乐榜，不能承诺强竞技公平。

推荐默认非穿透：一颗子弹最多结算一个目标，碰撞结算应确定；后续若设计穿透道具须显式改变规则版本。

## 游戏生命周期和重开

建议状态：主菜单 → 战斗 → 结算 → 重开；主菜单/结算可进入榜单。战斗提供暂停，避免打开全屏榜单时继续隐藏计算。

默认暂停规则：主动暂停、切后台、失焦或方向不适配均停止模拟与有效计时；返回前台不自动冲入战斗，需点击继续并给短恢复提示，清除残留输入。恢复提示长度是待定参数。每个状态只运行一个循环，不允许重复提交或计分。

结算主操作为“再来一局”，无需等待上一局成绩网络请求。上一局成绩以独立 run ID 排队/幂等提交；同步状态保留到确认成功或明确失败，网络恢复可重试，不用全局提交锁丢掉新局。离线可以练习，但不能未校验就宣称进入公开榜。

## 页面与状态清单

| 页面 | 首要信息与动作 | 必须覆盖的状态 |
| --- | --- | --- |
| 主菜单 | 一句话玩法、当前挑战、开始、个人最佳、榜单、音效 | 首次提示、挑战不可达/过期、可离线练习 |
| 战斗 | 飞机/敌机、得分、剩余时间、容错、道具状态、暂停 | 命中/受伤可辨认、增益到期、暂停、后台恢复、旋转提示 |
| 结算 | 本局分数、是否新最佳、分数构成、再来一局、榜单 | 同步中、成功、失败重试、离线待处理、成绩未通过校验 |
| 榜单 | 挑战/规则标识、排名与分数、自己的最佳、返回 | 加载、空榜、错误、旧缓存提示、挑战切换 |

像素美术用于飞机、敌机、背景和效果；正文、比分和按钮用清晰常规字体。避免像素字形妨碍手机阅读。画面信息优先于光效，敌机/子弹/道具不能只靠颜色区分。视觉设计不得把同步失败遮住，也不能把“已提交”当成“已验证上榜”。

## 重构实现边界建议

可将单文件拆分为：规则配置与版本、确定性模拟/碰撞、输入适配、渲染/音效、UI 状态机、成绩同步，以及 API/存储。先用玩法原型验证体验，再选具体渲染技术；不为重构而预先承诺更换框架。

原型保留在 Git 历史/既有分支供回看；历史榜单与新规则榜分开，不直接清空已有成绩。新方案实现前形成明确任务与验收，关联 STATUS 的 AF 缺陷；文档提交不夹带业务代码。

## 试玩要回答的问题

首次玩家能否无需长说明开始？一局是否短但有节奏变化？受击是否可理解而非突然误判？熟练玩家能否通过操作而非运气提高分数？结束后是否愿意立即重开？不同设备是否在相同视野和规则下比较？同步失败是否清楚且不阻断再玩？

记录不同水平玩家的完成率、平均局长、重复尝试和失败原因，再调整数值；这些指标目前没有实测数据，不能填入虚构目标达成率。
