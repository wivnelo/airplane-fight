# 像素 Figma 设计交接要求

[项目入口](../README.md) · [推荐玩法/UI](GAME_DESIGN.md) · [设计当前状态](../STATUS.md#figma-设计状态)。本页定义交付内容，不是已经完成的画稿。实际链接、额度阻塞和评审进展只在 STATUS 更新。

## 视觉方向与范围

围绕短局休闲拼分，用像素飞机、敌机、道具与背景建立风格；比分、正文与按钮采用清晰常规文字，手机可读性优先。可重构旧布局，不要求照搬原型；新机制与数值必须标为推荐草案。

## 需要交付的画面

| 画面 | 内容 |
| --- | --- |
| 主菜单 | 简短操作说明、当前挑战、开始、最佳分、榜单、音效；首次/离线状态 |
| 战斗 | 同比例场地、得分/时间/容错、道具反馈、暂停；命中/受伤/恢复/旋转提示 |
| 结算 | 本局分数与来源、新最佳、主按钮再来一局、榜单入口；同步中/失败/重试/未验证 |
| 榜单 | 规则版本/挑战标识、自己的最佳；加载/空榜/错误/缓存过期 |
| 适配与组件 | 手机优先竖屏、桌面同视野比例；按钮、字体、色板、图标、像素缩放规范 |

自动射击、150 秒、3 次容错、暂停/后台/横屏/榜单分组/非穿透均按 GAME_DESIGN 的推荐草案表达，不能以设计稿出现认定为最终批准规则。不加入未规划的养成、商店、付费或联机流程。

## 交接标准

1. 提供真实可访问的 Figma 页面/关键 frame、版本标识和评审结果；空文件不算成果。
2. 覆盖主要界面及加载/空/失败状态，标出候选行为和现有代码差异。
3. 说明字体、图标及像素素材来源与使用范围；没有实际资源则写待制作，不伪称已落地。
4. 碰撞/命中信息清晰，不只靠颜色辨识；触摸目标、手指遮挡、安全区和缩放可评审。
5. 用户评审后形成实现任务与验收；设计完成不等于代码完成、真机通过或发布。

额度受阻时不继续新建空文件；静态替代需用户选择后再执行。文档方案可以继续完善。
